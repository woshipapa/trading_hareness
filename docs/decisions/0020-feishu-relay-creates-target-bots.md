# 0020 飞书转发：用账号自己的会话在目标群里创建自定义机器人

- 状态：生效（2026-10-13）；取代 0019 的第 6 条；实现见 `feishu-relay/bridge/chat_bots.py`、`feishu-relay/adapter/webhook-targets.mjs`
- 日期：2026-10-13

## 背景

0019 让目标群的 webhook 可以在看板里填，但“在飞书群里加一个自定义机器人”仍要人做，理由是开放平台没有这个接口、用个人
账号调未公开的写接口有风险。用户 2026-10-13 明确：「可以看看我们当前的larkagentx和websocket是否具备添加webhook通过前端的
接口能力，这个是信任安全的，可以使用」，随后「这里可以试试让larkagentx去模拟试出类似的接口」。

当天查明并试过：

- 飞书网页端的群机器人面板（`openplatform` 模块的 `GroupBotModal`）不走私有协议命令创建机器人，而是调
  `https://open.feishu.cn/open-apis/chatbot/api/` 下的 HTTP 接口（`CreateWebhookBot`、`GetWebhookBotInfo`、
  `UpdateWebhookBotInfo`、`DeleteBotResource`），只凭登录会话的 cookie，没有另外的令牌。
- 群里已有哪些机器人、能加哪些机器人，是两条网关命令（13100、13101）；LarkAgentX 的命令表里没有它们，但对应的消息定义有。
- 用中继自己的会话在「运维通知群」试了一遍：创建、设关键词、不带关键词发送被拒（19024）、带关键词发送成功、删除，
  群里的机器人列表恢复原样。

## 决定

1. **新增目标群时不给 webhook 地址，就由中继自己建机器人。** adapter 请 bridge 在该群里确保有一个名为“转发机器人”的
   自定义机器人：没有就创建，有（同名且由本账号创建）就沿用；安全设置只用关键词，签名校验和 IP 白名单在这个机器人上关掉，
   因为中继发消息不签名。bridge 把 webhook 地址经带令牌的本机回环接口交给 adapter，之后的验证、加密入库与 0019 相同。
2. **只动自己建的机器人。** 识别条件是名称和创建者都对得上。别人建的机器人不沿用、不改设置、不删除，即使同名。
3. **删目标群时一并移除自己建的机器人**；移除失败（账号已退群、登录过期）不阻止删除目标群，看板提示去飞书里手动移除。
   手动填地址的目标群，机器人留在群里不动。
4. **手动填写仍然保留**，用于账号不在的群，或想沿用别人建的机器人。
5. **这些接口是网页端自己的接口，不是公开接口。** 它们随飞书网页端改版可能失效；失效时自动创建会报错，手动填写不受影响。

## 后果

- 新增一个账号已加入的目标群，只需在看板里选群。每次创建会在该群里出现一条“添加了机器人”的系统提示和一条测试消息。
- 建机器人是用个人账号做的写操作。频率很低（新增目标群时一次），bridge 里用一把锁串行执行，没有另设频率限制。
- 账号在目标群里没有加机器人的权限时（群设置只允许群主添加），创建会被拒绝并把原因带回看板。

## 怎样保证

- `feishu-relay/bridge/test_chat_bots.py`：同名但别人建的机器人不沿用也不删除；群机器人已满、群不允许加自定义机器人时
  在创建之前就拒绝；报错里不出现 webhook 地址；第二次调用不再创建。
- `feishu-relay/adapter/webhook-targets.test.mjs`：自动创建的目标群同样先发测试消息再入库；bridge 给的不是飞书机器人地址
  时不发请求；删除时只移除自己建的机器人。
