# 0010 盘后公共数据就绪与单写入方合同

- 状态：草案，待 owner / peer 确认；不是线上分工已经切换的记录
- 日期：2026-10-09

## 背景

两端重复补采公共日线会争用共享数据库；单一 daily_basic 门槛又把行情、估值、
复权及研究需求混在一起。Fuyao 已归档的估值没有进入 daily_fundamentals，造成
北交所记录覆盖不足。估值快照只提供部分指标，不能冒充完整每日指标。

## 提议

### 1. 时间与状态合同

每次请求必须带 `trade_date`、时区明确的 `as_of` 和合同版本。交易日用
Asia/Shanghai，持久化时间用 UTC。状态分别给出 `prices`、`limits`、
`valuation_records`、`valuation_fields`、`adjustments`、`suspensions`，不能用一个
`complete` 代替。每项给出 expected/eligible/missing、按交易所统计、缺失原因及来源。

- 名单用有效期 `[effective_from, effective_to)` 的 all_a 历史成员，且排除非股票。
- 行情按每个交易所至少 95% 名单覆盖判断；沪深覆盖不能掩盖北交所缺口。
- 已接收行情的涨跌停价与正值、语义合格的复权因子分别核对；不把 identity
  占位因子作为已修正除权的证明。
- 估值记录分母是已接收的有效个股行情；记录存在不等于字段可用。
- 估值消费者声明必需字段和口径：Fuyao `pe_ttm` → 列 `pe`、`pb_mrq` → 列 `pb`，
  raw.field_basis 保留映射，pe_mrq 单独保留。负 PE/PCF 是数值，NULL/非有限数是缺失。
- 换手、量比、市值、股本不从估值比率反推或填零。依赖它们的消费者必须逐股排除
  缺字段项，并显示排除数量。不能把 Fuyao 估值绑定成“完整 daily_basic”能力。
- capability resolver 的 required_fields 检查实际值；NULL、空字符串、非有限数
  不能因“键存在”而通过，零值和负值仍是有效测量。
- 停牌有独立的“已完成请求且结果为空”证据；零行不能自动认定没有停牌。

### 2. 原时点与补数后状态

同时保留两个读口径：

1. `session_evidence`：原交易日结束前、或消费者指定原决策时刻已经落库的数据。
2. `current_repaired_evidence`：截至当前 as_of 的历史修复结果。

新投影的 available_at 是投影入库时刻，并在 raw 中保留原证据 effective_at、
available_at 与摘要。周末补齐周五记录不会改变周五原时点完整率。既有原时点
研究 SQL 的次日零点边界继续生效；历史修复研究必须明确选择修复后口径并保留新收据，
不能通过倒填时间让旧收据成功。

### 3. 主责、复用和接管

提议由 Windows owner 从 16:00 启动公共阶段，peer 先检查同日就绪证据；已就绪则
复用，只跑自己的研究阶段。peer 最早 16:10、且主责租约过期时才允许补采。
这些时刻需要双方确认，不能仅靠各自流水线开始时间错开来保证互斥。

公共入口 `full_market_daily`、`core_daily_controls`、`daily_control_reconciliation`、
估值投影、复权补数和手动重跑都必须使用同一按日期的公共写入租约
`shared-post-close-data-v1:<trade_date>`：

- 租约 TTL 120 秒、40 秒心跳，取得 holder 与递增 fence 后才能写。
- 事务入口及提交前核对 holder/fence/有效期；后台线程继承操作截止时间，逐批
  写入检查取消状态，失效立即回滚。恢复的 owner 不能与接管中的 peer 同时写。
- 租约不可达、心跳失败或未知 ownership 时拒绝写入；不能绕到独立任务租约下写。
- 公共写入完成后重新读取各项就绪，已成功状态可复用；估值缺失继续报告缺口。
- 两端研究流水线自己的租约仍保留；公共数据复用不授权重复运行同一研究写入阶段。

### 4. 补数责任与研究门槛

| 数据 | 主责及补数 | 使用条件 |
| --- | --- | --- |
| 当日日线、涨跌停 | 公共阶段主责；过期后由公共租约接管方补采 | 日期、交易所覆盖、价格字段校验 |
| 估值 | peer 归档原始 Fuyao 证据，公共投影写入方复用；原始证据缺失才由指定采集方补采 | PE/PB 必需字段、口径及真实 available_at |
| 换手、量比、市值、股本 | 完整每日指标来源主责；没有字段就标缺失 | 所需字段逐股验证 |
| 累计复权因子 | owner 因子维护任务；接管必须复用同一公共租约 | 正值、语义、窗口完整性 |
| 涨停明细、候选台账、研究快照 | peer 研究阶段 | 每个消费者独立声明所需数据项与原时点 |

价格形态阶段只由自身价格/复权/板块/资金等实际需求阻断；需要估值的阶段额外
检查估值字段。现有“全部研究依赖 daily_control_reconciliation”的依赖图不能
直接放开，必须先审计各阶段消费字段并新增回归测试，避免以“纯行情”名义漏掉实际依赖。

## 本地已准备的估值修复入口

`python -m app.datasources project-valuations --trade-date YYYY-MM-DD` 默认只预览；
`--apply` 才写入。读取已有同日 15:00 以后的原始估值，仅投影有 canonical 日线和
有效名单且缺少每日记录的股票，不覆盖既有来源。原始证据全部缺字段时拒绝投影。
批量写入一条 INSERT、事务锁互斥、重复运行不重复记录，完成后读回记录与字段覆盖。
控制面每日记录读口改为按股票选择并合并来源，返回逐股 source_provider/
source_available_at/source_metadata 和字段覆盖。不能继续只选“覆盖最多的一个来源”，
否则 Longhu 与 Fuyao 的互补记录无法通过控制面读取。原交易日时间边界仍保留。
读口支持显式 `as_of` 的 repair_as_of 模式，并在结果标出时间口径；既有调用默认
仍为 session_end。周末修复后的研究调用需显式接入这个模式并同步其它输入时间边界，
当前线上流水线不因存在新函数而自动获得历史补数访问。

`DAILY_VALUATION_PROJECTION_ENABLED` 默认 false。配置为 true 才将投影接入估值归档
完成后的回调；投影 partial/blocked 时不会将归档任务标为 done，按原窗口重试。
该配置必须只在双方选定的写入方开启。当前投影事务锁只保护同一个估值投影入口，
**尚不能代替上述跨阶段 holder/fence 合同**；跨阶段接入和迁移对齐完成前不启用自动写入。

## 验收与生效条件

本次不增加 DDL。合并候选需通过隔离空库初始化、真实 PostgreSQL 投影验收与全量测试。
双方公共入口接入相同租约后，再验收：正常主责→peer 复用、owner 离线→peer 过期接管、
owner 恢复→只复用、线程超时→业务事务回滚、历史补数→原时点保持不变。

上线后必须读回新源码版本、同日数据就绪、研究收据及缺字段排除数量。
本合同不授权删除分钟旧行、停止双写、维护数据库、重装隧道或发布切换。
