# 0022 飞书转发：可以借用群里已有的自定义机器人发消息，但不改它、不删它

- 状态：生效（2026-10-13）；补充 0019 的第 3、4 条和 0020；实现见 `feishu-relay/bridge/chat_bots.py`（`existing_custom_bots`、`adopt_custom_bot`）、
  `feishu-relay/adapter/webhook-targets.mjs`（`addExisting`）、`feishu-relay/adapter/target-registry.mjs`
- 日期：2026-10-13

## 背景

“目标群”页列出本账号是群主的所有群之后，擒龙、尾盘掘金这类群显示“没有机器人”，要发会员到期提醒只能再建一个“转发机器人”，
建的时候还会在客户群里发一条测试消息。用户 2026-10-13：「擒龙群有机器人的webhook你需要检查itougu的那个监听」。

查到的事实（只读探测，`docs/work/probes/2026-10-13-group-bots-probe.*`，地址只按哈希在内存里比对）：这两个群各有一个手工建的自定义机器人，
itougu 监听（edge 上的 `itougu-neican.service`，地址在 `/etc/itougu-neican.env` 的 `ITOUGU_FEISHU_WEBHOOKS`）就是通过它们发消息的；
群主的会话读得到这些机器人的设置和地址。

## 决定

1. **本账号是群主的群，可以把群里已有的自定义机器人接成这个群的发送出口。** 地址由 bridge 用账号自己的会话从飞书读出，交给 adapter
   加密存进 `feishu_group_relay_webhook_targets`（0019 第 3 条的同一个存放处）。没有人经手地址，也不从别的服务的环境文件里抄。
2. **不发测试消息。** 0019 第 4 条的“保存前先验证”是为了挡住填错的地址；这里的地址是刚从这个群的机器人上读到的，比发一条消息证明得更多，
   而且不往客户群里放东西。手填地址和自动建机器人仍然先发测试消息。
3. **不改、不删。** 0020 的规则不变：只有名叫“转发机器人”、由本账号创建的机器人才会被中继修改或移除。借用的机器人 `managed = false`，
   删目标群时机器人留在群里；它的名字、关键词、安全设置中继都不动。
4. **关键词跟机器人走。** 机器人有关键词就把第一个放在中继发出的文字开头；没有就不加。
5. **开了签名校验的机器人不接。** 中继发送时不带签名。

## 后果

- 同一个地址现在有两处存放：原来用它的服务自己的配置，和中继的库。在飞书里重置了这个机器人的地址，两边都要更新；中继这边重新点一次“用已有机器人”即可。
- 借用之后这个群成为转发目标的一行，也可以被选作转发的目标群；撤回同步的观察名单会包含它，原服务经同一个机器人发的消息对不上中继的送达记录，会被忽略。
- 两个程序经同一个机器人发消息，共用飞书对单个机器人的频率限制。

## 怎样保证

- `feishu-relay/bridge/test_chat_bots.py`：列表里没有地址；接入只调用读取接口；开签名的、应用机器人、别的群的机器人都被拒绝。
- `feishu-relay/bridge/test_target_registry.py`：不是群主的群在读任何机器人之前就被拒绝。
- `feishu-relay/adapter/webhook-targets.test.mjs`：接入不发测试消息；`managed` 为假；删目标群不调用移除机器人。
