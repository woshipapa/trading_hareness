# 0029 只读状态路径只合并当前请求

- 状态：生效
- 日期：2026-10-16

## 背景

研究台由多个面板组成，服务状态、实时工作台和 provider 面板可能在同一刷新周期请求相同只读接口。owner 数据库经反向隧道访问，状态读模型原来在一个事务内顺序执行 16 个查询；重复 HTTP 请求和可合并的相邻查询会放大连接池与网络往返开销。

## 决定

共享 JSON client 只对没有 `AbortSignal` 的相同 GET 路径合并当前仍在执行的 promise。promise 成功或失败后立即删除，下一次读取重新访问服务端；带取消信号的请求保持独立。

`intraday_runtime_status` 在同一只读事务内用有界 `UNION ALL` 查询合并最新扫描/最新完成扫描、最新板块报告/曲线、最新投递/最近 20 条投递历史，以及两类待重试计数。合并只保留数据库原生列类型，不把时间戳转换成客户端缓存或字符串快照。

## 后果

相同刷新时刻的重复 GET 不再占用额外 HTTP、连接池或带宽；状态读从 16 个数据库往返降到 12 个。没有引入旧数据 TTL，因此暂时不会隐藏新故障。SQL 合并仍需在 owner 运行后用真实耗时和锁等待复核，不能把本地测试的查询数直接当成线上收益。

## 怎样保证

前端测试验证并发相同路径只发一个请求、settle 后下一次读取会重新发请求；取消请求仍走独立路径。量化 overlay 测试验证状态证据字段和查询顺序，数据库读失败仍沿原有异常路径返回。该决定不改变任何 provider、策略阈值、信号资格或投递写入。
