# 0030 研究横截面读取与盘口逻辑池提升到 200

- 状态：生效
- 日期：2026-10-16

## 背景

观察池 admission ceiling 已经提升到 200，但盘口逻辑池仍在 160，分钟横截面研究 API 仍在 50。两处都是本地软件截断：盘口的 Tencent 单次 80 只请求已经由编排层拆批，Parquet 读取也不需要把 50 当成硬件边界。

## 决定

将 `INTRADAY_ORDER_BOOK_MAX_SYMBOLS` 的进程软件上限提升到 200，将分钟横截面研究 panel 的读取上限提升到 200。盘口默认值仍为 80，owner 可按资源水位显式提高；Tencent 单请求最多 80 只、licensed Longhu 的 8 路并发、Longhu 单页 300 行和研究只读语义继续保留。

## 后果

完整 200 只观察池可以得到盘口覆盖，Tencent 兜底按 80/80/40 分批，不会静默截断。研究台一次可读取最多 200 只的分钟序列，减少客户端为同一研究窗口拆分请求的需要；响应体和 Parquet 解码内存随请求规模增加，因此默认值不随 ceiling 一起上调。

## 怎样保证

回归测试验证 1,000 的盘口环境值被压到 200、200 只 fallback 产生 80/80/40 三批且全部返回，分钟 panel 输入 250 只只保留 200 只。该决定不改 provider 请求合同、策略规则、信号门槛或任何订单路径；实际 owner CPU、RSS、数据库写入和隧道速率仍需交易日采样。
