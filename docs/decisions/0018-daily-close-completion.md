# 0018 盘后日线补齐与逐股完成判定

- 状态：生效（2026-10-13）；实现见 `daily_close_completion` 盘后阶段
- 日期：2026-10-13

## 背景

收盘全市场任务仍以 95% 的覆盖率门槛接受自己的供应商结果；这条门槛不变。但接受收盘任务不等于每只名单股票都有可用日线。2026-09-21 之后，原先停止运行的 Tushare 补洞没有替代路径，缺口统计为：09-21 缺 136 只、09-23 缺 105 只、09-24 缺 89 只、09-28 缺 153 只、10-08 缺 122 只、10-09 缺 141 只、10-12 缺 71 只。控制面还要求复权因子、涨跌停和基本面；收盘自己的场外行本来就不写基本面，这个问题另行处理。

补洞请求使用 Longhu 的按日期逐股 K 线。该接口返回前复权序列，并以 `CQ` 标记除权除息；若请求日之后发生事件，请求日的价格已经不能代表当时成交价格。

## 决定

1. 95% 仍是收盘任务自身的接受规则；一个交易日只有在 `all_a` 名单的每只股票都有日线，或有明确的 `not_traded`、`adjusted_later`、`unverified`、`invalid`、`failed` 等原因时，才称为完成。补齐阶段不改变收盘任务的 95% 门槛。
2. 缺失股票逐只请求并显式解析 `CQ`。请求日之后有标记的股票跳过，不把后来调整过的价格写回历史日；请求日当天有标记的股票不写复权因子；`CQ` 缺失或与日期未对齐时不写入。
3. 涨跌停价沿用股票自己的最近五个、四十个自然日内且已有涨跌停价的历史行，取最常见的比例并四舍五入到 0.01；只接受 5%、10%、20%、30%。北交所向昨收方向取整，其他市场按分位半入。写入前用当天已经有涨跌停价的名单行验证，吻合率低于 99.5% 就全部保留为 `limits_pending`。
4. 不使用 `market_rules.a_share_limit_ratio`。2026-10-12 的只读测量显示它只能复现约 94% 的已存涨跌停价：主板 ST 在 2026-07-06 后被按 10% 处理而交易所仍为 5%（141 只）、北交所按半入而不是向内取整（176 只）、代码前缀 302 被当成 20% 板（1 只）。携带本股票历史比例的规则在该日复现 99.98%。
5. 复权因子只有在请求日前已有语义有效的 `longhu_qfq_derived` 因子，且请求日之后的第一条因子（如有）与之前相等，同时请求日没有除权除息标记时才携带写入；否则保留 `factor_pending` 及原因。2026-10-12 的手工修复按这个规则写入 814 条因子。
6. 2026-10-12 的人工修复共补 818 条日线，并以 150 只样本逐字段核对开、高、低、收、昨收、成交量、成交额均相等；这次补齐把同一规则变成可重复的盘后入口。每次运行都留下 `quant.fetch_runs` 收据，供控制面和健康检查读取。

## 后果

- 每个交易日收盘后最多增加 600 个逐股请求；超过上限或收盘/控制尚未落地时阻断并留下收据，下一次运行再尝试。
- 发生后来除权的股票仍会显示为未补齐，避免把前复权价格冒充历史成交价；除权日也不会凭空生成复权因子。
- 补齐行的 `available_at` 是补齐时刻，因此点时读者不会把事后证据当成当时已知；当前可见的老师回放读者可以看到它们。
- 场外行的基本面缺口没有在本决定中补造。是否为场外行建立可审计的基本面来源是一个开放问题。

## 怎样保证

- `daily_close_completion` 紧跟 `full_market_daily` 运行，阶段预算为 600 秒；它允许 `completed`、`partial`、`blocked`、`failed` 收据继续被盘后编排器记录。
- 日线、涨跌停和因子写入前在同一数据库事务内重新读取，已存在的行不被覆盖；统一使用现有 Tushare normalizer 和 Longhu provider key。
- `daily_control_reconciliation` 和老师导入的 `repair_daily` 都调用同一个补齐入口，避免出现两套修复逻辑。
- `data.daily_bars_complete` 在上海时间 18:45 后检查最新收据；没有收据或状态不是 `completed` 就失败，并显示未完成原因的数量及前五只股票。18:45 前和闭市日不判断。
- 单元测试覆盖阶段顺序、`partial` 收据、重试顺序、老师修复、健康检查的无收据/部分/完成/时间窗口情形；发布路径使用工作树挂载运行完整 unittest 套件。
