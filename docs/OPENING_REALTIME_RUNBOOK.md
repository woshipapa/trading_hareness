## 观察性盘口与分钟证据

- 腾讯单票盘口把最多 **40** 个观察标的合并为一条请求，每 3 秒保存五档买卖盘、内外盘和累计量额。涨停/跌停的单边盘口也会保留，并记录封单量；单边时 QI 为 `+1/-1`，OFI 保持未定义，供后续封单侵蚀研究使用。相邻快照只在同一中国交易日、间隔不超过 15 秒时使用 `max(累计差分, 0)`，以免交易所日切、循环中断或上游重置制造伪成交；由此得到 QI1/QI5、最佳档 OFI 近似和区间 VWAP。
- 显式观察池默认 40 只，可通过 `INTRADAY_WATCHLIST_MAX_SYMBOLS` 明确提高到最多 100 只；超过当前配置时扫描会 fail-closed 并记录 `watchlist_capacity`，不会截取前缀却声称全覆盖。盘口单批仍最多 40 只，扩展观察池由采集层分批完成。
- 腾讯分钟带只包含每分钟收盘和累计量额。因此同刻量能、30 分钟量价相关性与 smart-money VWAP/Q 只用于研究归因；它不是逐笔数据，也不改变既有入场、减仓或止损阈值。
- 五档原始观察默认只保留 7 天（可由 `INTRADAY_ORDER_BOOK_RETENTION_DAYS` 在 1–30 天内调整）；每日首次连续竞价采样前清理过期行，避免高频 JSON 证据无界占用 SSD。

## 飞书投递规则

- 盘中策略只有在已有二次确认（默认 5 分钟窗口内的后续扫描）或硬止损/明确首观测例外时，才会进入飞书投递。
- 每一条消息先写入本地 outbox；发送成功才计入 10 分钟冷却。发送失败会在后续扫描中最多重试三次，即使原始行情条件已消失也不会丢失。
- 消息包含上海观测时间、腾讯量价/流入证据、可用的 Super GET 交叉确认、决策卡链接和“人工复核、非交易指令”提示。
- 连续三次投递失败会在运行状态面板降级并持久化；恢复后的首条成功正常投递会追加运维恢复回执。
- 板块轮动提醒独立于五分钟完整快报：盘中每 `60` 秒比较东财相邻一分钟、同一分类下的板块净流，取同类变化前 5% 且至少 `2.0` 亿变化、当前绝对净流至少 `1.0` 亿。跨零（流出转流入或反向）和单方向急剧加速都必须由下一分钟保留方向才会提醒；同一方向键 10 分钟冷却。五分钟仅用于较重的完整 Top10 综合快报，不影响轮动检测或轮动飞书。
- 板块轮动事件及其飞书投递回执保留 60 天，随后由板块循环每日清理；它们是从相邻一分钟快照得出的可重建控制证据。原始板块快照同样保留 60 天，日线、原始行情与研究证据不在此清理范围内。

## 明早开盘前检查

正式预检不向市场源发测试请求，只检查本地控制面：

```bash
./scripts/quant-opening-preflight.sh
```

该预检应在远端 owner/peer 上执行，读取远端 Docker、数据库和健康接口：确认四个关键容器在运行、已应用 Alembic 版本、竞价事件、全 A Level-1、公开证据、盘中扫描、Super GET、腾讯五档、板块曲线、分钟基线、复盘、盘后和日终摘要等后台租约均存在，数据库和有界执行器可用，早盘扫描 `5s`、午后高频窗口 `10s`、Super GET `1s`、腾讯五档 `3s`（每批 40 只）、板块曲线 `60s`、飞书通道 `ready`，以及最近 30 小时内的 PostgreSQL + 工作流备份可通过 archive listing、manifest、权限和 workflow JSON 校验。它还会核对已发布的分析师报告/消息工作流分别使用有界的 25/20 条文本页，并检查当前发布图是否已有成功回执；分析师未晋级前后者只给非阻断告警，实时策略权重仍固定为零。它不会 restore、刷新行情、调用代理或向群里发送测试消息。本地只通过 owner API 查看结果，不把本地容器健康当作远端验收。

如果仅在排查尚未生成首份备份的新环境，可临时跳过备份检查（不建议作为正式开盘流程）：

```bash
./scripts/quant-opening-preflight.sh --skip-backup
```

已确认、投递中或投递失败的板块轮动证据可由前端代理只读查看：

```bash
curl -fsS http://127.0.0.1:5680/api/research/intraday/board-rotations/latest | jq
```

其中 `confirmed` 表示下一分钟方向已确认，`alerted` 表示飞书回执已成功；这个读取不会刷新东财或任何行情源。
