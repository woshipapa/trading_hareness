# A股数据供应商与库：口碑、文档限制与常见坑

调研日：2026-10-13。只引用本次打开过正文的页面；检索摘要里出现、但打开失败或正文未渲染的数字，放在 Gaps，不当成已核实事实。证据等级：**(a)** 已打开页面上的官方约束，或页面内给出的可复核样例/实测描述；**(b)** 论坛、专栏、转载、营销文中的个人说法，没有可复核的行数或价差表。官方文档只说明设计意图，不证明用户回测正确。

厂商条目字段：来源 URL、日期、作者类型、官方能力、独立来源指出的坑、证据等级、查不到的点。

## 独立开发者（而不只是厂商）说什么会出错？

### Takeaway

免费库和本地行情软件的坑，主要是复权算法彼此不同、停牌被填成“有价格”、财务字段把公告日和报告期混在一起，以及东财类接口会无声断连。付费终端（Wind / Choice / iFinD）在公开网页上几乎只有定位和价格传闻，没有打开到的、带数字的公司行为或 point-in-time 对账。

### Cited Findings

#### Tushare（tushare.pro）

- 来源 URL：<https://tushare.pro/document/2?doc_id=290>、<https://tushare.pro/document/2?doc_id=28>、<https://tushare.pro/document/2?doc_id=146>、<https://tushare.pro/document/2?doc_id=33>、<https://tushare.pro/document/2?doc_id=25>。页面无发布日期（打开日 2026-10-13）。作者类型：官方文档。
- 官方能力（积分，a）：120 积分每分钟 50 次、每天 8000 次，只能调非复权日线。2000 分以上每分钟 200 次、每个 API 每天 10 万次，年费表列 200 元。5000 分以上每分钟 500 次、常规数据无总量上限，年费表列 500 元。10000 / 15000 分对应特色数据，年费表列 1000 / 1500 元。分钟、港美股、公告等不在积分里，要单独买。历史分钟（1/5/15/30/60）历史起点写 2009 年，单独 2000 元/年，每分钟 500 次、每次 8000 行。机构价写为个人的 10 倍。积分按年有效、不退款。
- 官方能力（复权，a）：`adj_factor` 2000 积分起、5000 以上可高频；写明盘前 9:15–9:20 入库，由 Tushare 自行生产。`pro_bar` 用该因子动态计算，**HTTP 调不了**，要求 Python SDK ≥ 1.2.26。公式：前复权 = 当日收盘价 × 当日复权因子 / 最新复权因子；后复权 = 当日收盘价 × 当日复权因子。同一页写明：前复权从用户设定的 `end_date` 往前锚，不是从“今天”往前锚，所以和行情软件/财经网站的前复权会不同；复权是“分红再投”。同一页又写“目前只支持 A 股的日线复权”，但下文给了周线、月线例子，参数表的 `freq` 还包含 1MIN。这是文档自相矛盾，不是用户实测。
- 官方能力（财务与股票池，a）：`income` 至少 2000 积分，单股票历史；全市场某季要 `income_vip`，5000 积分。字段同时有 `ann_date`（公告日期）、`f_ann_date`（实际公告日期）、`end_date`（报告期）。`start_date` / `end_date` 的参数说明是“公告日”起止，不是报告期。`report_type` 从 1 合并报表到 12，含调整前、母公司、单季。输出有 `update_flag`，但该页没有定义 0/1。样例里 600000.SH、公告日 20180428、报告期 20180331 出现两行相同记录。`stock_basic` 2000 积分、每分钟 50 次、单次最多 6000 行；`list_status` 默认 **L（上市）**，另有 D 退市、P 暂停上市、G、UN；有 `delist_date`。输入说明写“G 未交易”，输出说明写“G 过会未交易”。官方示例只演示 `list_status='L'`。
- 独立来源指出的坑：2026-07-13 掘金《Tushare接口文档：复权因子》(<https://juejin.cn/post/7661841699346382867>，个人转述) 写“每日 8:30–9:30 更新”、单次最多 6000 行、停牌日复权因子会补齐而日行情没有、因子是“累计后复权因子”。这些句子**不在**本次打开的官方 `doc_id=28` 上（官方写的是 9:15–9:20，且没有停牌对齐和 6000 行）。转述和现行官方页不一致，不能当成现行约束。(b)
- 查不到的点：2024–2026 的官方破坏性变更清单；`ann_date` 与 `f_ann_date` 的差别；`update_flag` 取值定义；停牌日 `daily` 是否缺行（现行 `adj_factor` 页没写）；ST/*ST 5% 与北交所 30% 是否由行情接口给出涨跌停价。

#### Baostock（baostock.com）

- 来源 URL：<https://baostock.com/mainContent?file=pythonAPI.md>（打开日 2026-10-13；页内示例日期写到 2024-12-31，无“最后更新”字段）。作者类型：官方文档。
- 官方能力（a）：`query_history_k_data_plus` 日/周/月及 5、15、30、60 分钟；参数列表里没有 1 分钟。指数没有分钟线。`adjustflag`：3 不复权（默认）、1 后复权、2 前复权；文档写分钟、日、周、月都支持前后复权。算法名称是**涨跌幅复权**，并写明“不同系统间采用复权方式可能不一致”，“与同花顺、通达信等存在不同”。优点自述为：资金运用率保持 100%，分红不减少投入、配股不增加投入。代码参数说明只写 `sh` / `sz`。全文检索「北交所」「bj.」无命中。
- 停牌（a，这是填充而不是删行）：“股票停牌时，对于日线，开、高、低、收价都相同，且都为前一交易日的收盘价，成交量、成交额为 0，换手率为空。”`tradestatus` 1 正常、0 停牌。日线指标表标题是“包含停牌证券”。`isST` 1/0 在日线字段里。除权日的 `preclose` 不是前一日实际收盘，而是交易所公布的除权除息价；页内给了除息、送股、配股公式。
- 财务（a，字段有时点，但是否“入库滞后”没写）：`query_profit_data` 等季频接口返回 `pubDate`（公司发布财报的日期）和 `statDate`（季度最后一天，例子 2017-03-31、2017-06-30）。成长、营运、偿债、现金流、杜邦同样有这两个字段。页内没有写“公告后多久才能查到”，也没有写查询日早于 `pubDate` 时会不会返回该行。
- 独立来源指出的坑：未打开到 2024–2026 的、带代码和价差的 Baostock 实测帖。第三方技能文档里的“季报发布后约 2 个月才能拿到”“17:30 入库”**没有**出现在本次打开的官方 API 页（检索「17:30」无命中），不采用。
- 查不到的点：北交所覆盖；1 分钟线；财务数据相对 `pubDate` 的入库延迟；与 Tushare/通达信的价差行数；是否收费以外的用量上限（登录接口存在，但打开的章节没有 SLA 或积分）。

#### 主题如何落到上面的来源

- **复权口径不一致**：Tushare 官方写前复权锚在用户的 `end_date`、算法为分红再投，并承认和行情软件不同（a）。Baostock 官方写涨跌幅复权，并点名与同花顺、通达信不同（a）。AKShare 维护者在 #7250 要求对照目标网站的复权方式（a）。三套算法不是同一个定义。
- **停牌填充**：Baostock 官方把停牌日填成前收、量额为 0，而不是删掉该日（a）。Tushare 现行已打开页面没有写停牌是否补行。聚宽未核实。
- **涨跌停无法成交却在回测中成交**：本次没有打开到 2024–2026 聚宽官方撮合页。2016 年前后社区帖只证明当时有滑点和成交量比例，不能证明现在涨停单会被拒绝或放行。
- **ST/*ST 5% 与北交所 30%**：交易所规则见凤凰网对北交所交易规则的转述（<https://finance.ifeng.com/c/v002IZoAciho3ieN-_6QHaC3I0fZ2R6zOXzbKkxIgX--RJbDA__>，页内写 11 月 2 日发布规则；检索未给出可靠的 2024–2026 修订日期）。涨跌幅限制比例 30%；向不特定合格投资者公开发行的股票上市首日，或退市整理期首日，不设涨跌幅。这是规则新闻，不是某数据商算错的实测。(a) 限于该文所引规则文本。掘金 2026-10-06 教程把主板 10%、创业板/科创板 20%、北交所 30%、ST 5% 写成连板判断阈值（<https://juejin.cn/post/7693144953568591923>，个人）。它是在警告“一刀切 10% 会算错”，没有展示某个供应商的错误行。(b) Baostock 日线有 `isST`，但打开的字段表没有涨停价。Tushare 已打开的行情页也没有 ST/北交所涨跌停幅度。
- **point-in-time：公告日 vs 报告期**：Tushare `income` 同时给公告日、实际公告日、报告期，且日期过滤参数写的是公告日（a）。字段存在不等于回测用了公告日。Baostock 季频有 `pubDate` 与 `statDate`（a），没有写查询时点是否会提前看到未公告报表。
- **幸存者偏差与退市股缺失**：Tushare `stock_basic` 默认只要 `list_status='L'`，退市在 `D`，需另请求；有 `delist_date`（a）。默认调用会把退市股排除在列表外。没有打开到“退市股行情缺了多少行”的计数。
- **分钟线/Tick 质量**：AKShare 东财 1 分钟只覆盖近 5 个交易日且不复权，并警告非最近一个交易日开盘价为 0（a，文档约束）。Tushare 分钟是单独付费权限（a）。Tick 丢包没有可引用的供应商级数字。
- **多源对账不一致**：见下一节。已打开材料里，能量化到具体价格的只有 AKShare 官方对 600734 后复权负值的复现，以及 Tushare/Baostock 文档里的算法差异，不是两家库的逐日价差表。

### Inferences

- 把 Tushare 前复权、Baostock 涨跌幅复权、东财/AKShare 前复权、通达信前复权当成“同一个前复权”来对账，文档本身就预期会对不上，对不上不等于其中一家坏了。
- `stock_basic` 默认 `L`，再只对这批代码拉历史，会在样本构建阶段就丢掉后来退市的股票。这是接口默认值造成的幸存者偏差，不必等到行情里缺行。
- AKShare 的稳定性问题是结构的：README 承认接口可能被移除，维护者在封 IP 事件里改回同步请求，分钟线限制写在东财接口说明里。这些都不是“偶发网络错误”。
- 付费终端的“更准确”在本次公开材料里没有测量支撑。能写的只有价格传闻和产品定位。

### Gaps

- 聚宽现行文档因地区限制整站打不开。涨停单在回测里是否成交、停牌是否填充、复权锚点，都未核实。
- 掘金 2026-07-13 对 Tushare 复权因子的“停牌补齐、8:30–9:30、单次 6000 行”与已打开的官方页冲突，没有第三份来源裁定哪一版是现行文档。
- Wind / Choice / iFinD 没有打开到的 PIT 或公司行为质量测量。
- Level-2 没有点名供应商的丢 tick / 封单不一致测量。
- 未找到 Tushare 2024–2026 破坏性变更的官方列表。

## 如何把 (a) 实测或官方约束 和 (b) 论坛轶事分开？

### Takeaway

能标 (a) 的，几乎都是厂商自己写在文档里的限制或样例（积分门槛、复权公式、停牌填充、默认股票池、分钟窗口、后复权负值）。能标 (b) 的，是年费、收益被数据“飘了多少”、封 IP 的持续时间、以及未打开正文的 issue 细节。聚宽现行撮合规则两边都算不上：官方页没打开，论坛帖太旧。

### Cited Findings

**(a) 已打开的官方约束或文档内样例**

- Tushare 积分档、分钟单独计价、机构 10 倍、不退款：doc_id=290。
